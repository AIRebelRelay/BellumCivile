## ROOT CAUSE
The Native GetCourtAgendas API is a current-record snapshot, not a durable event log. Term rollover, invalid realm pruning, reaction-history expiry, claim-grace and rally cleanup can remove confirmed results before Bridge reads them. Native CourtObjectiveState and ResultApplied are distinct; UI notifications are not authoritative terminal receipts.

## Implementation and bounded queue
- Save keys: BC_CourtTerminalEvictionReceipts_v1 and BC_CourtTerminalEvictionOverflow_v1. Existing save definition already supports Dictionary<string,string>; no new class registration or save field.
- Limit: 1024 receipts; repeated pending IntegrationId is deduped. Overflow increments persisted counter and logs status=overflow, delivery_claim=false rather than deleting old pending facts. A full queue is **NOT lossless** and MUST block a release until Stage31G adds transport/ACK and the game shows no overflow.
- One bad record logs status=record_error without aborting subsequent eligible captures. Enumeration-level failure logs status=capture_error. Neither prevents Native Court cleanup. Invalid identity is logged and skipped.
- Technical cancellation with ResultApplied=false is NOT published and not represented as a completed political vote. No public Bridge, Relay, or AII event is generated by Stage31F.
- A recent-history entry can refer to an agenda already removed from the active list; pending map ID dedup protects duplicate capture while it is retained. Delivered-after-ACK tombstone semantics remain future Stage31G design work.
