# S23A — admission rules only, before runtime ownership

ROOT CAUSE: Revamp currently couples accounting, automatic foreign intent, ratification and terminal execution. A gate at the AI-parley entry alone can return false and trigger WarScore's forced raw resolution. A blanket ApplyTreaty gate would also affect player signing. This stage defines executable, side-effect-free admission semantics before touching those shared call chains.

TOUCH: new ForeignDiplomacyAdmissionPolicy.cs (readiness, source classification, verdicts); new Tests/ForeignDiplomacyAdmission*; candidate file/informational version and module version; build command example identity only; Tests/ModuleLocalLogs.Tests.ps1 updates its two hard-coded expected candidate versions only. Reassessed before editing: this is required by the metadata bump, not a logger/packager behavior change. No existing production method changes.
DO NOT TOUCH: WarPeaceRevampBehavior, WarScoreBehavior, ForeignTreatyBehavior, BlockVanillaForeignPolicyProposalsPatch, VoluntaryPactAiBehavior, CR/Bridge/Relay, persistence, councils, War Will, existing treaty effects, all engine action entrypoints.
MUST FIX: distinguish LLM intent, exact-draft consent precondition, crisis resolution, explicit hold, and unchanged legacy ownership. Activation must refuse missing readiness or pending/unknown legacy proposals. Claimed owner failure must never imply legacy permission.
MUST NOT CHANGE: all current gameplay; policy is not wired to any runtime caller. Pacts and hostage selection remain Bellum-owned. Legacy MCM defaults and save schema remain byte-identical.

Regression contract BEFORE implementation: complete readiness succeeds; every missing capability fails; default/null readiness fails; any nonzero (including unknown negative) pending count fails. Every defined source preserves disabled/out-of-scope behavior. Player/internal/client/existing obligations/pacts/hostages are excluded. Ordinary automatic war/peace/parley require LLM intent; owner loss holds. Ratification without bound consent holds, with consent only continues Native validation; no verdict claims applied. Terminal foreign conflict requests distinct crisis resolution, never permission for raw peace. Unknown in-scope source holds. Defaults fail closed.

Activation capabilities are prerequisites, not implementations: revamp enabled, campaign/scope binding, durable owner, durable queue/save recovery, gateway, exact-draft consent verifier, bounded crisis handler. This pure policy does not verify an engine fact or establish ownership itself. Runtime integration MUST construct these facts using trusted game-thread services; do not expose these flags as user settings.

Runtime wiring, durable owner registration/recovery, old pending-state inventory, source classification at real call sites, crisis implementation and native receipts remain OPEN. NO MCM switch is added. Do not install this candidate as an active LLM mode. No claim that source mapping tests prove engine classification or save safety.
